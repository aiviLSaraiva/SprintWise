# Plano inicial de testes

Esta lista reúne verificações que a equipe deverá fazer durante o desenvolvimento. Uma caixa marcada significa que o teste foi realizado e conferido; não significa que o sistema já passou por ele.

## Disciplinas, projetos e tarefas

- [ ] Cadastrar e consultar uma disciplina.
- [ ] Não permitir disciplina sem nome.
- [ ] Cadastrar projeto e tarefa com os dados necessários.
- [ ] Não permitir projeto ou tarefa sem título.
- [ ] Conferir se as tarefas ficam ligadas à disciplina correta.
- [ ] Conferir se os prazos respeitam as regras da proposta.
- [ ] Conferir os filtros de tarefas por disciplina, projeto, status, prioridade e prazo.

## Eventos

- [ ] Cadastrar e consultar um evento.
- [ ] Não permitir evento sem título ou disciplina válida.
- [ ] Mostrar eventos em ordem de data.
- [ ] Conferir se eventos aparecem separados das tarefas.

## Progresso e atrasos

- [ ] Projeto sem tarefas mostra 0% de progresso.
- [ ] Projeto com todas as tarefas concluídas mostra 100%.
- [ ] Projeto com algumas tarefas concluídas mostra o percentual correto.
- [ ] Conferir as classificações de risco conforme a regra RN06 da proposta.
- [ ] Conferir se eventos não alteram o progresso dos projetos.

## Salvamento dos dados

- [ ] Salvar disciplinas, projetos, tarefas e eventos.
- [ ] Fechar e abrir o programa e conferir se os dados continuam salvos.
- [ ] Conferir se as ligações entre os dados foram mantidas.
- [ ] Mostrar uma mensagem compreensível quando houver erro ao ler ou salvar um arquivo.

## Menus e consultas

- [ ] Conferir se os menus permitem acessar as funcionalidades.
- [ ] Mostrar tarefas pendentes e atrasadas.
- [ ] Mostrar prazos próximos e próximos eventos.
- [ ] Consultar atividades por disciplina.
- [ ] Mostrar o progresso dos projetos.

## Registro

Quando fizerem um teste, anotem quem testou, o resultado e o que precisa ser corrigido. Não marquem um teste como concluído antes de executá-lo.
